Panel USB protocol

How a PC drives the Blackmagic ATEM Micro Camera Panel over USB, with no ATEM switcher: authentication, every input, every display and every light.

Panel explorer

Click any part of the panel: a key, a knob, a display, a light. The panel on the right explains the report that carries it, the LEDs behind it and how to light them, with a ready-to-send example, and what RCP For All Camera does with it.

Click an element, or move with Tab and press Enter.

Status of the facts: key codes, knobs, lever, displays, matrix and all 75 LEDs were confirmed on a real panel. The names of key codes 0x59–0x5E are inferred from the order they were pressed in.

Feature reports must have their exact size. Padding a feature buffer to the 64-byte maximum makes the panel fail the request (ERROR_GEN_FAILURE). Output reports can be padded to 33 bytes.

Authentication

The panel sends nothing until the host authenticates, with the challenge and response of Blackmagic's DaVinci Speed Editor, on feature report 0x05. Each message is [05, command, u64 little endian].

SET 05 00 00×8          → GET 05: 05 00 <device challenge>
SET 05 01 00×8          → GET 05: 05 02 …              (host challenge, may be ignored)
SET 05 03 <response>    → GET 05: 05 04 <timeout, u16 s>  (the panel answers 600 s)

The response is computed from the challenge (internal/surfaces/micropanel/hid_auth.go, tested against three challenges a real panel accepted). Authenticate again before the timeout ends: RCP For All Camera does it every 400 s.

More info: ATEM Software Control

ATEM Software Control also authenticates the panel and overwrites its displays. Close it before driving the panel from another program: only one of them can own it.

Knobs: input and feature report 0x0E

Nine u16 little-endian absolute positions, 0 to 1024, in this order: WHITE R, BLACK R, WHITE G, BLACK G, WHITE B, BLACK B, the unlabelled top-right knob, SENS, COARSE. The panel counts the turns and stops at both ends. Input reports only come on change, so read the feature report at connect.

Iris lever and master black ring: input and feature report 0x0F

Three int32 little endian: [1, lever, ring]. The lever goes from -4096 (pulled back) to +4096 (pushed forward); the ring from about -4096 to +4096.

Outputs

Displays: output report 0x10

14 bytes, one per digit, raw segments: bit 7 = a, bit 6 = b, bit 5 = c, bit 4 = d, bit 3 = e, bit 2 = f, bit 1 = g, bit 0 = point. Digits: 0 ND, 1 CC, 2–3 MASTER GAIN, 4–7 SHUTTER, 8–10 IRIS, 11–13 MASTER BLACK.

10 00 00 00 00 EE 38 1E 3A 00 00 00 00 00 00   "Auto" on SHUTTER

Camera matrix: output report 0x11

7 rows × 10 columns, 2 bits per pixel (0 off, 1 red, 2 green, 3 amber). Pixel p = row × 10 + col is in byte p >> 2, bits 2 × (p & 3), least significant first.

Lights: output report 0x02

A 30-byte bitmap, LED n = bit n & 7 of byte n >> 3, followed by a layer number. Every light is on layer 0, indices 0 to 74.

Pitfalls

  • Light layers persist in the panel, even across a host restart, and a bit set on any layer lights the LED. A host that only uses layer 0 must clear layers 1 to 5 when it starts.
  • Keep LED bits above 74 at 0: setting them draws stray shapes on the camera matrix.
  • Use two handles on the HID device, one for the blocking reads, one for writes and feature reports: Windows serialises the I/O of a synchronous handle.
  • Input reports come only on change: read features 0x0E and 0x0F at connect to know where the knobs and the lever are.
